Date: 2026-08-01

Scope: branding, local-data import, Egyptian phone normalization, worker OTP, and stale Expo Router declarations.

## 1. Root cause for each defect

1. **Branding:** `app.json` already used the current `warsha-brand-*` native assets and active headers already used `BrandLogo`, but the checked-in splash PNG and its renderer still contained the superseded tagline `YOUR WORK. OUR MISSION.`. Auth/loading UI did not consistently render the reusable brand component. The physical-device native icon can also remain stale when only Metro is reloaded.
2. **Local import:** addresses used PostgREST `upsert(..., { onConflict: 'customer_id,local_source_id' })`, but the database uniqueness rule was a partial index. PostgreSQL cannot infer that partial index from the generated conflict target, producing `42P10`. Legacy mock favourite IDs were also non-UUID strings and could not be inserted into the UUID foreign key. The two client-side writes were not one transaction.
3. **Phone normalization:** the old helper only stripped a few formatting characters and required an already-valid international E.164 value, so Egyptian local numbers were rejected before submit.
4. **Worker OTP:** the captured request reached hosted Supabase successfully. It was the existing-customer phone-enrollment stage (`auth.updateUser({ phone })`, hence `/auth/v1/user`), not signed-out OTP initiation. A read-only hosted `/auth/v1/settings` check returned `external.phone=false`; hosted phone Auth/SMS was disabled, and GoTrue returned HTTP 500 `unexpected_failure`. The prior catch collapsed that into a generic sign-in error and logged the raw oversized error.
5. **Router warnings:** the root stack declared leaf paths owned by child navigators (`booking/new/[providerId]`, `booking/[id]`, and `provider-job/[id]`) and declared a nonexistent `addresses` route. The correct root names are the `booking` and `provider-job` segments; the deep navigation destinations remain valid.

## 3. Migration created

`202608010001_device_p1_fixes.sql` replaces the partial address index with an inferable full unique index on `(customer_id, local_source_id)` and adds `import_local_customer_data(uuid,jsonb,uuid[])`.

The RPC is `SECURITY DEFINER` with an empty `search_path`, is executable only by `authenticated`, compares `auth.uid()` with the expected account, bounds and validates its payload, imports addresses and discoverable UUID favourites in one transaction, and is idempotent on retry. It was applied only to the local reset database. It was not pushed to hosted Supabase.

## 6. Local-data import behavior and retry guarantees

- The device copy is never deleted or mutated.
- Addresses and supported favourites are validated before the RPC.
- Malformed supported data stops before remote writes.
- The RPC is atomic: any server-side failure rolls back the whole supported-data import.
- Address identity is `(account, local_source_id)`; retry updates the same address rather than adding another.
- Favourite identity remains `(account, provider_id)`; duplicate UUIDs are deduplicated and database conflict handling is idempotent.
- Non-UUID legacy mock IDs and UUIDs that do not identify a currently discoverable professional are reported as skipped partial data.
- The active session is checked before the call, and the RPC independently rejects no-auth and account-switch cases.
- Bookings and attachment files are never included in the RPC. A device with only excluded bookings is not prompted to import supported data.
- The marker is written only after success/explicit partial success. Failure offers an actionable retry and leaves the marker unset.

## 7. Egyptian phone normalization rules

The only supported mobile prefixes are centralized as `010`, `011`, `012`, and `015`. The helper accepts:

- `01099221106`
- `1099221106`
- `201099221106`
- `+201099221106`
- harmless spaces, dashes, and parentheses

All normalize to `+201099221106`. Wrong lengths, unsupported Egyptian prefixes, extra/misplaced plus signs, punctuation other than the harmless characters, and foreign numbers are rejected without guessing a `+20` prefix. The visible input is not rewritten while typing; a canonical preview is shown and submit uses the canonical value. The same helper covers worker sign-up/sign-in, OTP verification, customer phone enrollment, and mobile-wallet payout values only when that payout destination type is selected.

## 8. Exact OTP failure cause and corrections

Hosted Auth phone support is disabled (`external.phone=false`). The failing `/auth/v1/user` request was `updateUser` while an email customer was adding a phone. This was not a localhost/LAN failure: the hosted endpoint was reachable.

Before any phone mutation, the app now reads the safe Auth capability endpoint and fails closed with a specific phone-provider message. It validates the current user server-side for customer enrollment, canonicalizes Supabase's returned phone representation, requires authoritative `phone_confirmed_at`, and relies on `activate_provider_role` to recheck `auth.users.phone_confirmed_at` before worker creation. Email/password sessions are not replaced during customer upgrade.

Development logging now emits only operation, safe code, HTTP status, fixed sanitized message, retryability, target environment, and data mode. It never logs tokens, OTPs, cookies, headers, sessions, or private metadata.

Local Auth uses Supabase fixed `test_otp` fixtures. A clearly non-secret placeholder Textlocal config only enables the local GoTrue provider gate; app code permits only the two mapped fixture numbers on a local target, so it cannot attempt provider delivery. The hint is gated by both `__DEV__` and a local Supabase URL. Hosted/production capability remains fail-closed.

## 9. Physical-device LAN configuration

At failure time, Expo loaded the hosted URL `https://lrhipbcapzfxuwixfoog.supabase.co`; it was reachable from the device and the request reached Auth. It was not using `127.0.0.1`.

For the current local retest, this workstation's Wi-Fi address is `172.20.10.4`, and `http://172.20.10.4:54321/auth/v1/settings` was reachable with phone support enabled. The ignored `.env.local` uses that URL. Do not commit this IP: it can change whenever the network changes.

Supabase JS derives REST, Auth, Realtime, Storage, and Functions from the one base URL on port `54321`; no client service URL is permanently hardcoded to localhost or the private IP.

Windows Firewall may need Private-network inbound allowances for Metro TCP `8081` and local Supabase gateway TCP `54321`. The iPhone and workstation must be on the same Wi-Fi/hotspot, without client isolation, and Expo Go must have Local Network permission.
